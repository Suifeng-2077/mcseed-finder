目标：拿到某个 Minecraft 世界（level）的种子 seed。
Minecraft 把世界的种子保存在存档的 level.dat 文件里，位于
NBT 标签 Data.WorldGenSettings.seed。

本程序就是想办法把这个 level.dat 里的 seed 读出来。


## Minecraft 1.16.1 + mcsrfairplay 的存档结构
一个世界的存档目录（...\saves\<世界名>\）里，关键文件：

  level.dat          → 世界数据，里面含 seed。可能是明文 gzip，也可能是加密的
  mcsrfairplay\worldDataKey.txt → 加密世界的"钥匙"，用来解 level.dat

mcsrfairplay 这个 mod 会把 level.dat 加密：
  worldDataKey.txt = 一段 AES 加密后的密钥
  level.dat        = 用那把密钥 AES 加密后的 gzip NBT 数据


## 程序取 seed 的三种方式（按优先级）
1. plain 明文直读
   如果 level.dat 是明文 gzip（前两字节是 1F 8B），
   直接解 gzip → 解析 NBT → 取 Data.WorldGenSettings.seed。
   最常见、最干净、不碰游戏进程。

2. enc 密钥文件解密
   如果 level.dat 是加密的，但 worldDataKey.txt 存在：
     解 worldDataKey.txt → 得到密钥
     用密钥解 level.dat → gzip → NBT → seed
   需要程序内置的 mcsrfairplay 主密钥（这就是为什么整合包版本必须一致，
   版本不同主密钥就变了）。

3. hunt 零痕迹内存扫描（兜底）
   当 level.dat 加密、且还没有 worldDataKey.txt、且游戏正在运行时：
     从游戏进程外读内存（ReadProcessMemory），扫描内存里的世界密钥
     找到后解密 level.dat 得到 seed。
   特点：不注入游戏、不加载额外组件、不在游戏日志留任何痕迹。
   速度：通常 1 秒内完成，需要游戏在运行。


## 关键点：为什么整合包版本必须一致
方式2、3 解密都依赖 mcsrfairplay 内置的主密钥。不同版本的 mcsrfairplay
主密钥可能不同。本程序内置了 1.2.1 的主密钥，所以：
  MC 1.16.1 + mcsrfairplay 1.2.1  → 能解
  其它版本                         → 解密失败，读不出 seed


## 三种方式的取舍
  plain：最优先、零副作用、创建后立刻可用
  enc  ：次优，需要密钥文件存在
  hunt ：兜底，需要游戏运行，通常 1 秒内完成，零痕迹（不注入游戏、不留日志）

程序按 plain → enc → hunt 顺序尝试，哪个成功用哪个。
捕获记录的"方式"列（plain/enc/hunt）会告诉你用了哪一种。
